* For vault-wide canonicalization or dedupe passes, make a backup archive of `~/my-data` first before broad edits. If using Claude Code for the cleanup, expect that a full-vault pass may need multiple runs or `--continue` because the first pass can hit max-turn limits or get interrupted. After Claude finishes, do a manual verification pass on the changed notes and search for leftover anti-patterns like `Recent Interactions`, `Reasoning`, or duplicated operational details still sitting in people/entity notes.
* When doing cross-note dedupe cleanups (especially with a coding agent like Claude Code), do not stop after the first pass. Re-read the edited entity note and verify that it contains only identity facts plus lightweight links/pointers. Agents may leave behind summary lines that still include operational specifics like cadence, schedules, or checklist details. If that happens, run a tightening pass so those specifics live only in the canonical task/project/note that owns them.
* If a note becomes non-canonical during cleanup, default to converting it into an archived pointer note rather than deleting it. Keep it tiny: set status to archived, add one short handoff sentence pointing to the canonical note, trim related links to lightweight breadcrumbs, and preserve the changelog so the audit trail still makes sense. Delete only when the file is pure throwaway noise with no historical value.
